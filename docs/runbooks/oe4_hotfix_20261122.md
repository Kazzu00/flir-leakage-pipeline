# OE4: autorización comunicada y ejecución sin infraestructura de firmas

Para el relanzamiento posterior al fallo 808329 usar la
[recuperación del contrato de entrenamiento](oe4_recovery_20261122.md).
El registro de autorización permanece vigente; las rutas anteriores se conservan
como historial y no se reutilizan para las nuevas ejecuciones.

Este hotfix reemplaza el requisito de firmas OpenSSH solo para OE4. El responsable
del proyecto comunicó el 2026-11-22 que JP autorizó los tres experimentos AUG_OFF y
su evaluación posterior. Se registra esa comunicación en
`configs/closeout/oe4_authorization_20261122.yaml`, con
`cryptographically_verified=false` y `documentary_approval_verified=false`.
El software no autentica a JP ni afirma haber revisado un documento de aprobación.
Los SHA-256 siguen vinculando bytes y operaciones, sin presentarse como firmas.

El usuario reportó preflight remoto READY, job 808314, exit 0 y bundle previo de
358 archivos verificados. Es evidencia comunicada; este hotfix no ejecutó SSH ni
revalidó ese job. El cambio de código exige otro freeze: no reutiliza el recibo
anterior ni modifica originales.

## Contrato de ejecución

- Protocolo nuevo: `oe4_closeout_v2`.
- Nuevo freeze/salidas: `$HOME/flir-oe4-hotfix-20261122/`.
- Test común anterior: `$HOME/flir-oe4-closeout-20261121/common-test`, verificado
  en lectura. Publicación, ZIPs, pesos y las tres corridas AUG_ON conservan sus rutas.
- Preflight copia el registro de autorización dentro del freeze sellado y liga
  sus bytes, configuración, código, datasets de desarrollo y fuentes.
- Submission y ambos workers llaman al mismo `authorize`; este ejecuta
  `verify_freeze` y verifica la comunicación congelada antes de acceder a GPU.
- Cada fase publica un registro inmutable bajo `authorizations/train` o
  `authorizations/evaluate`; evaluar exige los tres recibos COMPLETED_AUG_OFF
  con política correcta, protocolo v2, el mismo freeze/autorización/pesos,
  `test_used=false` y hashes de argumentos, historia y checkpoints.
  El registro de evaluación liga los tres SHA de recibos y se comprueba de nuevo
  en cada worker. No se acepta un recibo AUG_OFF del protocolo anterior.
- No se requieren claves, firmas, allowed_signers, configuración de root ni
  variables para desactivar controles. Los protocolos históricos ajenos a OE4
  mantienen sus contratos.

Los tres AUG_OFF usan exactamente los miembros y bytes train/val congelados de
sus respectivos AUG_ON, el mismo `yolo11m.pt` inicial verificado, seed 42, 50 épocas,
SGD, batch 1 y 640. Se conservan todos los controles no operacionales y se apaga
solo aumentación. Las vistas copiadas evitan cachés sobre los datos originales.
El guard del loader contrasta membresía y anotaciones; se comprueban los argumentos
efectivos y la historia completa. El test no entra en entrenamiento.

Se mantienen validación de checkpoints, hashes, procedencia, identidades,
grupos protegidos y controles de disyunción. La proximidad temporal se reporta
como candidata; no se convierte en independencia demostrada ni leakage confirmado.
El test se evalúa en otra fase después de los tres AUG_OFF, con la misma
configuración y las seis selecciones last epoch 50. No se ejecutan entrenamiento
ni inferencia en el portátil.

## Transferencia desde PowerShell

El hostname consta en el handoff existente. El usuario introduce únicamente su
usuario SSH habitual; no se infiere una cuenta ni se altera `.ssh/config`.

```powershell
$HypatiaUser = Read-Host 'Usuario de Hypatia'
$Bundle = 'C:\Users\LENOVO\Desktop\flir-oe4-hotfix-20261122\flir-oe4-hotfix-20261122-code.tar.gz'
scp -- $Bundle ($Bundle + '.sha256') "${HypatiaUser}@hypatia.uniandes.edu.co:"
ssh "${HypatiaUser}@hypatia.uniandes.edu.co"
```

## Preflight nuevo y entrenamiento en Hypatia

El paquete conserva el script `scripts/hypatia/preflight_oe4.sh`. Usa el entorno
existente `$HOME/.venvs/flir-detection/bin/python` y comprueba las versiones
8.3.203 / torch 2.7.1 / torchvision 0.22.1. El código anterior y su freeze se
conservan. Ejecutar desde una ruta nueva evita atribuir el hotfix al código viejo.

```bash
set -euo pipefail
cd "$HOME"
sha256sum -c flir-oe4-hotfix-20261122-code.tar.gz.sha256
test ! -e flir-oe4-hotfix-20261122-code
tar --keep-old-files -xzf flir-oe4-hotfix-20261122-code.tar.gz
cd "$HOME/flir-oe4-hotfix-20261122-code"
bash scripts/hypatia/preflight_oe4.sh
bash scripts/hypatia/submit_oe4.sh train
```

El preflight se ejecuta en CPU; el submit requiere READY antes de `sbatch`.
Array 0-2%1: histórica, aleatoria y C10, secuenciales con una GPU por tarea.
Logs: `$HOME/flir-oe4-hotfix-20261122/logs/train-%A_%a.{out,err}`.
Si el preflight falla por integridad, conserva BLOCKED y el entrenamiento no se
envía. No se reescribe ni se borra el freeze anterior.

Después de completar correctamente los tres entrenamientos:

```bash
cd "$HOME/flir-oe4-hotfix-20261122-code"
bash scripts/hypatia/submit_oe4.sh evaluate
```

El registro de autorización ya incluye evaluación; no hay un segundo documento
manual que crear. El código verifica los tres recibos completados antes de
liberar esta fase. Después de las seis evaluaciones:

```bash
bash scripts/hypatia/aggregate_oe4.sh
squeue -u "$USER"
sacct --format=JobID,State,ExitCode,Elapsed
```

## Validación local

Resultados del checkout del hotfix: 67 pruebas focalizadas aprobadas y 19
regresiones nativas de detector/recibos/red/orden de importación aprobadas.
Ruff global, formato de archivos del adaptador y `git diff --check` aprobados.

Las pruebas son sintéticas y offline. Incluyen autorización sin llamar al
verificador SSH, manipulación de fuente/test/freeze/pesos/autorización, rechazo
de recibos incompatibles, requisito de los tres completados, autorización dentro
de ambos workers antes de GPU y ejecución real de Bash → verificación del bundle
→ CLI → autorización → `sbatch` simulado. La simulación comprueba entrenamiento,
bloqueo prematuro de evaluación, evaluación tras tres recibos y bloqueo por
manipulación. El worker se prueba desde un spool con rutas con espacios.

El paquete se construye desde commit limpio con
`build_bundle.py --name flir-oe4-hotfix-20261122-code`; dos construcciones deben
coincidir en SHA-256. Se verifica la extracción completa y se repite la suite
focalizada importando el código del paquete. La entrega registra resultados
observados, commit y checksum. No se afirma ejecución en Hypatia.
